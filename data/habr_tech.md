# Кнопка под постом в Telegram одна на всех. Как я сделала личные напоминания

Под постом в канале нельзя показать разным читателям разные кнопки. Это не ограничение API, которое обходится хитрым флагом, — это устройство Telegram: разметка принадлежит сообщению, а не человеку. Личного состояния в канале не существует.

Мне нужно было именно личное состояние: читатель отмечает матч, который хочет посмотреть, и за десять минут до начала получает ссылку на трансляцию. Дальше — как это делается, и четыре ошибки, которые по дороге стоили дороже самой задачи.

Проект — телеграм-канал с ботом: 56 модулей, 26 700 строк на Python, aiogram 3, PostgreSQL, Render. Канал публикует девять рубрик в день сам, бот обслуживает подписки, партнёрские ссылки и пару мини-приложений.

## Три канала связи вместо одного

Развязка нашлась не в коде, а в постановке. Пост, нажатие и личное сообщение — это три разных канала, и путать их не нужно:

- **пост в канале** видят все, он общий по определению;
- **нажатие** (`callback_query`) видит только бот — читатель не знает, кто ещё нажимал;
- **личное сообщение** получает один человек, и там разметка уже персональная.

Значит, в канале живёт не состояние, а счётчик. Кнопка показывает число отметившихся и ничего больше:

```python
rows.append([InlineKeyboardButton(
    text=f"🔔 {title[:38]}", callback_data=f"tmatch_{tour}_{match_id}")])
```

А переключатель «напоминать / не напоминать» уезжает в личку, где у каждого своя клавиатура и колокольчик честно показывает состояние.

## Бот не может написать первым

Второе ограничение, и оно жёстче первого: бот не имеет права начать переписку. Читатель канала, который никогда не запускал бота, недоступен — ему просто некуда отправить напоминание.

Здесь выручает малоизвестная возможность `answerCallbackQuery`: в ответ на нажатие можно вернуть URL, и Telegram откроет его у нажавшего. Если это ссылка на самого бота с параметром, человек попадает в бота одним касанием, а `/start` приходит уже с полезной нагрузкой:

```python
async def _deep_link(payload: str) -> str:
    username = await database.get_setting("bot_username")
    return f"https://t.me/{username}?start={payload}" if username else ""


async def _open_bot(call: CallbackQuery, payload: str, fallback: str):
    url = await _deep_link(payload)
    if url:
        await call.answer(url=url)
    else:
        await call.answer(fallback, show_alert=True)
```

Вызывается это так: `await _open_bot(call, f"tm-{tour}-{match_id}", NO_CHAT)`. Дальше обработчик `/start` разбирает `tm-atp-401`, находит матч и дооформляет подписку — человек ничего не вводит.

Одна деталь, на которой я потеряла вечер: обработчик `/start tm-` перехватывал сообщение целиком, и новый пользователь не видел ни приветствия, ни выбора языка. Лечится явной передачей хода дальше:

```python
@router.message(F.text.regexp(r"^/start\s+tm-"))
async def start_with_match(message: Message, bot: Bot):
    await _handle_match_start(message, bot)
    raise SkipHandler          # иначе общий /start не отработает
```

## Ошибка, которая молчала

Механизм заработал, и сразу же перестал. Читатель нажимал «напомнить» и получал «🔕 напоминание снято». Каждый раз. В логах — ничего.

Причина: колонка `starts_at` объявлена как `TIMESTAMP` без пояса, а в неё приходило время с поясом, `datetime.now(timezone.utc)`. asyncpg падает на этом внутри, исключение перехватывалось обёрткой «база недоступна», запись не создавалась. Код видел, что подписки нет, и честно сообщал: значит, её сняли.

```python
# Колонка объявлена как TIMESTAMP без пояса, а сюда приходит время
# с поясом. asyncpg на этом падает изнутри, ошибка глоталась,
# и кнопка отвечала «снято».
if starts_at is not None and starts_at.tzinfo is not None:
    starts_at = starts_at.astimezone(timezone.utc).replace(tzinfo=None)
```

Вторая половина починки важнее первой. Функция теперь возвращает `None` вместо `False`:

```python
except Exception as e:
    # None, а не False: «не сохранилось» и «снято» — разные вещи,
    # и читателю надо сказать правду.
    logging.error(f"Напоминание не сохранено: {e}")
    return None, 0
```

Правило, которое я вынесла: у операции три исхода, а не два. Получилось, не получилось и «сделали обратное». Когда третий исход сливают со вторым, ошибка живёт неделями.

## Матч перенесли. Или отменили. Или нет

Расписание берётся из ESPN, и оно меняется по ходу дня. Раз в десять минут бот сверяет время начала у всех, кому ещё предстоит напомнить:

```python
async def refresh_times(bot: Bot = None) -> int:
    waiting = await database.pending_matches()
    fresh, dead = {}, {}
    for tour in {t for _, t in waiting}:
        data = await tennis_live.fetch_scoreboard(tour)
        for match in tennis_live._singles(data, tour, big_only=True):
            if _cancelled(match):
                dead[match["id"]] = match.get("state") or ""
            elif _starts(match):
                fresh[match["id"]] = _starts(match)
    ...
```

Соблазн был такой: если матча больше нет в выдаче — значит, отменили, надо сказать людям. Так делать нельзя. Исчезнуть матч может и потому, что его перенесли на другой день, и потому, что источник моргнул. Сообщение «матч отменён» о матче, который состоится, — это хуже молчания.

Поэтому решение принимается только по явному статусу:

```python
CANCELLED = ("cancel", "postponed", "walkover", "abandoned", "suspended")

def _cancelled(match) -> bool:
    return any(word in (match.get("state") or "").lower() for word in CANCELLED)
```

## Маркировка рекламы, которая уезжала во второе сообщение

Под книгами стоят партнёрские ссылки, а это реклама со всеми обязанностями распространителя: в объявлении должен быть виден токен `erid`. Не в ссылке — в самом посте. Магазинов четыре, у каждого свой рекламодатель, ИНН и токен, то есть до четырёх строк маркировки.

Подпись под фотографией в Telegram — 1024 символа. У книги с длинным описанием подпись упиралась в предел, и хвост уезжал в следующее сообщение. Формально это реклама без маркировки; штраф — до 500 000 рублей.

Чинится не увеличением лимита, а решением, чем жертвовать:

```python
def _fit(text: str, tail: str, has_media: bool) -> str:
    """Хвост — это маркировка; она обязана остаться при объявлении.
    Длинным бывает описание, его и укорачиваем."""
    limit = MAX_CAPTION if has_media else MAX_MESSAGE
    if len(text) + len(tail) <= limit:
        return text + tail

    room = limit - len(tail) - 1
    if room < 200:          # пометки сами длиннее поста — резать нечего
        return (text + tail)[:limit]
    cut = text[:room]
    edge = max(cut.rfind("\n"), cut.rfind(" "))
    return (cut[:edge] if edge > room // 2 else cut).rstrip() + "…" + tail
```

Была и вторая, тихая часть той же ошибки. Рекламодатель искался по хосту ссылки, а у ссылки через CPA-сеть в адресе стоит сама сеть:

```
https://ad.advcake.ru/click?erid=...&ulp=https%3A%2F%2Flitres.ru%2F...
```

Магазин спрятан внутри параметра. Бот не находил пометку и выводил голый токен — без названия юрлица и ИНН, то есть маркировку неполную. Теперь имя магазина ищется и внутри раскодированного адреса.

## «SSL/TLS required», которое означало не то, что написано

Однажды перестали сохраняться вообще все записи. Ошибка: `InvalidAuthorizationSpecificationError: SSL/TLS required`. Три дня это означало не то, что написано, и вот почему.

**Пул создавался лениво.** При старте всё поднималось, а отказ вылезал через час, когда понадобилось новое соединение. Чтение шло по старым живым соединениям, запись требовала нового — и падала. Лечится проверкой живым запросом сразу после создания пула:

```python
_pool = await asyncpg.create_pool(dsn, min_size=1, max_size=3,
                                  init=_init_connection, ssl=ssl_mode)
# Создание пула само по себе ничего не доказывает: соединения
# открываются по мере надобности, и отказ вылезает потом.
async with _pool.acquire() as probe:
    await probe.fetchval("SELECT 1")
```

**Наружу летела ошибка последней попытки.** Кандидатов два — шифрованное соединение и открытое. Падали оба, а поднимался только последний `last_error`, то есть отказ открытого. Настоящая причина — почему не вышло шифрованное — оставалась в логах, куда никто не смотрит.

**Список попыток лежал в общей переменной.** Пока один вызов дописывал вторую строку, соседний начинал свою попытку и обнулял список. В отчёт попадала половина правды, причём каждый раз разная. Починилось локальным списком, который выкладывается целиком в конце, плюс замком вокруг сборки пула — без него десяток обработчиков, столкнувшихся на упавшей базе, собирали по своему пулу каждый.

И главное: диагностика переехала из логов в сам продукт. Команда `/db` показывает адрес без пароля, способ связи, наличие таблиц, последнюю ошибку и подсказку, что с этим делать. А бот теперь пишет владельцу при запуске, если базы нет: без этого он выглядит совершенно живым — меню открывается, сообщения приходят, — и что всё уходит в пустоту, выясняется случайно.

## No open ports detected

Render проверяет открытый порт сразу после старта. А бот сначала делал всю долгую работу — создание таблиц, загрузка картинок разделов, теннисный рейтинг, проверка ключей, — и только потом открывал порт. При задержке до внешней базы в 100 мс это секунд тридцать, и всё это время деплой пишет «No open ports detected», а иногда не дожидается вовсе.

Порядок изменился на обратный: порт открывается сразу после сборки роутеров, долгая часть уходит в фоновую задачу.

```python
server = await asyncio.start_server(make_handle_ping(bot, dp), "0.0.0.0", port)
logging.info(f"Ping & API & Webhook server started on port {port}")

# Порт занят — теперь можно заняться долгим. Render ждёт открытого
# порта, а не готовности базы.
asyncio.create_task(warm_up(bot))
```

## Тесты, которые читают исходник

Тестов не было вовсе, пока за неделю не случилось четыре ошибки подряд. Две из них — падения запуска, и обе видны разбором кода, без единого запуска.

Первая: `import` внутри функции делает имя локальным на всю функцию, с первой её строки. Я дописала в `main()` блок с `import admin` — и `dp.include_router(admin.router)` строкой выше перестал видеть модуль, импортированный в начале файла. `UnboundLocalError`, деплой лежит.

```python
@pytest.mark.parametrize("name", MODULES)
def test_no_local_import_shadows_a_module(name):
    tree = ast.parse((ROOT / f"{name}.py").read_text(encoding="utf-8"))
    top = {a.asname or a.name.split(".")[0]
           for node in tree.body if isinstance(node, (ast.Import, ast.ImportFrom))
           for a in node.names}

    shadowed = []
    for fn in ast.walk(tree):
        if not isinstance(fn, (ast.AsyncFunctionDef, ast.FunctionDef)):
            continue
        for node in ast.walk(fn):
            if isinstance(node, ast.Import):
                for a in node.names:
                    local = a.asname or a.name.split(".")[0]
                    if local in top:
                        shadowed.append(f"{name}.py:{node.lineno} — {local}")
    assert not shadowed, "локальный import затеняет модуль: " + "; ".join(shadowed)
```

Вторая — обращение к объекту бота раньше его создания в той же функции. Проверяется так же: находим строку, где `bot` присваивается, и убеждаемся, что раньше к нему не обращаются.

Тем же способом ловятся ещё три вещи, каждая из которых молча отключает кусок продукта:

- роутер, забытый в `include_router`, — раздел просто перестаёт отвечать;
- кнопка меню без обработчика — при нажатии не делает ничего, и заметить это почти невозможно;
- долгая работа до открытия порта — та самая история с Render.

Это дешёвые тесты: они не запускают код, а читают его. Зато ловят ровно тот класс ошибок, который не ловится юнит-тестами, потому что до юнит-теста дело не доходит — падает импорт.

## Проверка проверок

Набор тестов, который никогда не падал, ничего не доказывает. Я отключила сдвиг расписания на выходных, сохранение маркировки и определение партнёрской метки в ссылке — и прогнала снова. Упали четыре теста, ровно те, что должны были. Потом вернула код и убедилась, что снова зелено.

Пять минут работы, и это единственный способ узнать, что тесты вообще что-то проверяют.

## Что из этого стоит забрать

Ограничение платформы — это не стена, а развилка. Общая кнопка не мешает личному уведомлению, если перестать делать их одним механизмом.

Молчаливая ошибка дороже громкой. Кнопка, которая врёт «снято», живёт неделями; упавшая чинится за час. Поэтому у операции должно быть три исхода, а диагностика — жить в продукте, а не в логах, куда владелец не заходит.

И последнее, менее техническое. Я не бэкенд-разработчик — продакт с медицинским образованием. Половина решений в этом проекте не программистские: не показывать погоду в канале, потому что пост один на всех, а город у каждого свой; не говорить «матч отменён», пока это не сказал источник; резать описание, а не маркировку. Написать код сегодня может кто угодно. Решить, чего делать не надо, — пока нет.
