# Площадка картин: архитектура

Не галерея. Каталог с подтверждённым авторством, приём чужих работ,
оценка, продажа и статистика реализованного — с возможностью собирать
выставки из уже проданных вещей.

Документ описывает устройство и порядок сборки. Он намеренно начинается
не с кода: два решения ниже определяют всё остальное, и принимать их
после написания кода дороже, чем до.

---

## 1. Что решается до первой строки кода

### 1.1. Налоговый режим — блокирующее

Самозанятость с этой затеей несовместима. Запрет прямой: закон о НПД
(422-ФЗ, ч. 2 ст. 4) не допускает перепродажу чужих товаров и отдельно
называет тех, кто ведёт дела **в интересах другого лица** по договорам
поручения, комиссии или агентским. Продажа чужих картин за процент —
ровно это.

Значит, до приёма первой чужой работы нужно ИП. Свои картины на НПД
продавать можно и дальше: это своё, а не чужое.

Что из этого следует для архитектуры: **деньги за чужие работы не
должны проходить через личный счёт**. Разделение отражено в модели
данных — у каждой сделки есть сторона-продавец, и она не всегда
владелица площадки.

### 1.2. «Музейная оценка через сервис» — такого сервиса нет

Экспертизы подлинности и стоимости делают люди: ВХНРЦ имени Грабаря,
НИНЭ, эксперты музеев. Интерфейса для программ у них нет и не будет —
результат экспертизы это документ с подписью, а не ответ на запрос.

Поэтому две разные вещи, которые нельзя смешивать:

| | **Экспертиза** | **Ориентир цены** |
|---|---|---|
| Кто делает | эксперт, человек | программа |
| Результат | документ с подписью | диапазон и сравнимые продажи |
| Автоматизируется | нет | да |
| Можно обещать | только как услугу-посредничество | как справку, не более |

В системе экспертиза — это **процесс со статусами и документами**, а не
интеграция. Ориентир цены — данные аукционов (Artprice, AskArt, из
русских — Bidspirit, lot-online).

Ловушка, которой надо избежать: написать на витрине «оценено музейными
экспертами», когда это ориентир по аукционным данным. Это то же, чем мы
занимались в теннисе с причиной снятия: **не утверждать того, чего
источник не говорит**. Здесь цена ошибки выше — тут деньги и чужая
собственность.

## 2. Где это живёт

**Каталог — сайт, не бот.** Три причины, и каждая достаточна:

1. Коллекционеры не листают Telegram в поисках живописи. Они приходят
   по ссылке, из поиска, из письма.
2. У провенанса должны быть постоянные адреса: запись о работе —
   ссылка, которую вставляют в договор и в каталог выставки.
3. Выставка — это страница, которую отправляют куратору и площадке.
   Экран бота такой ссылкой не является.

**Бот — пульт оператора и приёмная.** В нём: приём работ от художников
(фотографии удобнее слать с телефона), уведомления о заявках,
управление статусами, переписка с покупателем. То, что уже работает в
`art_shop.py`, остаётся — расширяется модель.

```
  Художник ──фото, описание──► Бот (приём)
                                 │
                                 ▼
                          База (работы, авторы,
                          провенанс, оценки, сделки)
                                 │
            ┌────────────────────┼────────────────────┐
            ▼                    ▼                    ▼
       Сайт-каталог         Бот-пульт           Статистика
       (публично)         (владелица)          реализованного
            │                    │
            ▼                    ▼
       Страница работы      Заявка покупателя
       Страница автора      Сделка, документы
       Страница выставки
```

## 3. Модель данных

Существующая таблица `artworks` рассчитана на одного автора — свои
картины. Её надо расширять, а не заводить вторую: две таблицы работ
разойдутся на первой же правке.

### party — сторона

Любой участник: художник, коллекционер, галерея, музей. Одной таблицей,
потому что один и тот же человек бывает и автором, и покупателем.

```
id, kind (artist|collector|gallery|museum), name, legal_name,
contacts, inn, verified_at, note
```

### artwork — работа

```
id, artist_id → party, title, year, technique, materials, size,
signature (где и как подписана), edition (для тиража),
status, owner_id → party, created_at
```

Статусы — машина состояний, и переходы между ними не произвольны:

```
draft → submitted → review → appraised → listed → reserved → sold
                       │                            │
                       └──► rejected                └──► withdrawn
```

`sold` не удаляет работу из каталога. Проданное — самый ценный раздел:
оно показывает, что здесь покупают, и из него собираются выставки.

### artwork_photo

Отдельно, потому что работ с одной фотографией не бывает: общий вид,
фрагмент, подпись автора, оборот холста, рама.

```
id, artwork_id, file_id (Telegram), url, kind (main|detail|signature|
back|frame), ordering
```

### provenance_event — цепочка владения

Главная ценность всей затеи. Не поле в карточке, а **события**:
владение меняется, и история важнее текущего состояния.

```
id, artwork_id, kind (created|acquired|sold|gifted|exhibited|
restored|appraised|published), happened_on, from_party, to_party,
document_url, source, note
```

Правило: событие без источника существует, но помечено как
неподтверждённое. Каталог обязан показывать разницу между «есть
документ» и «со слов владельца».

### appraisal — оценка

```
id, artwork_id, kind (authentication|valuation), org, expert,
requested_at, finished_at, verdict, value_amount, value_currency,
document_url, status (requested|in_progress|done|refused)
```

### price_signal — ориентир по рынку

То, что считается программой. Отдельно от `appraisal` намеренно: смешав
их в одной таблице, мы однажды покажем аукционную статистику как
заключение эксперта.

```
id, artist_id, artwork_id (если та же работа), source, lot_url,
sold_on, hammer_amount, currency, size, technique
```

### deal — сделка

```
id, artwork_id, seller_id → party, buyer_id → party,
price_amount, currency, commission_amount, status,
contract_url, paid_at, handed_over_at
```

`seller_id` отдельным полем — то самое следствие из 1.1: площадка
должна знать, чьи это деньги, и не смешивать свои продажи с чужими.

### exhibition / exhibition_item — выставка

```
exhibition: id, title, starts_on, ends_on, venue, curator_note, status
exhibition_item: id, exhibition_id, artwork_id, owner_consent_at,
                 insured_value, loan_from, loan_to, condition_note
```

Выставка из проданных работ — это заём у владельцев. Поэтому
`owner_consent_at` обязателен: без согласия вещь в список не попадает,
и это проверяется кодом, а не памятью куратора.

## 4. Порядок сборки

Каждый этап даёт работающую вещь. Ни один не требует следующего, чтобы
иметь смысл.

### Этап 0 — бумаги (без кода)

ИП, агентский договор или договор комиссии, условия приёма работ,
правила возврата. Без этого этап 2 незаконен.

### Этап 1 — свой каталог с провенансом

Расширить `artworks`, добавить `party`, `artwork_photo`,
`provenance_event`. Завести свои работы: фотографии, описания, история
создания. Сайт-каталог со страницей работы и страницей автора.

Проверяемый итог: есть ссылка, которую не стыдно отправить.

### Этап 2 — приём чужих работ

Форма в боте: фотографии, описание, запрошенная цена, документы.
Статусы `submitted → review`. Уведомление владелице. Отказ с причиной.

Проверяемый итог: первый чужой художник подал работу и получил ответ.

### Этап 3 — оценка

Ориентир цены по аукционным данным — автоматически. Экспертиза —
процесс: заявка, выбор организации, оплата, документ, статус. В карточке
работы они показываются **раздельно и разными словами**.

### Этап 4 — сделки и статистика

Сделка со статусами и документами. После `sold` — событие в провенанс.
Статистика реализованного: сколько, за сколько, за какой срок, по
авторам и техникам. Это же — главный довод для следующего художника.

### Этап 5 — выставки

Сборка из проданных работ, согласия владельцев, страница выставки,
печатный список.

## 5. Что здесь может сломаться

**Обещание, которое не выполняется.** «Оценим у музейных экспертов» —
если эксперт откажется или запросит сумму, которой нет у художника.
Решение: оценка — отдельная платная услуга с ясной ценой, а не часть
приёма работы.

**Ответственность за подлинность.** Разместив чужую работу, площадка
отвечает за то, что о ней написано. Никогда не утверждать авторство,
которое не подтверждено документом: в карточке — «со слов владельца» до
тех пор, пока не появится бумага.

**Деньги.** Приём платежей за чужие вещи — только после ИП и только
через расчётный счёт. Личная карта в этой схеме не участвует нигде.

**Вывоз.** Работы старше пятидесяти лет и предметы культурной ценности
требуют разрешения Минкультуры на вывоз. Для покупателя из-за рубежа это
не мелочь, а срок и документы.

**Пустой каталог.** Главная причина смерти таких площадок. Поэтому
этап 1 — свои работы: каталог не должен открываться пустым, когда
придёт первый чужой художник.
